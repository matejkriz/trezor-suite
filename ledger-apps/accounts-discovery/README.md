# Accounts Discovery for Ledger Flex

A standalone public-data-only Ledger application for Trezor Suite discovery.
Open this app once, approve public account export on the device, and Suite can
request account xpubs and address keys across supported networks in batches.
Normal network backends still determine which accounts have transaction history.
There is no signing support: sending funds still requires the corresponding
Ledger network application.

The implementation uses Ledger's current Rust device SDK, pinned to 1.37.0.
Ledger's C boilerplate is maintained for existing applications; its maintainers
recommend the Rust boilerplate for new apps. The protocol and derivation policy
are specified in [PROTOCOL.md](PROTOCOL.md).

## Supported scope

- BTC, BTC testnet/regtest: legacy, nested SegWit, native SegWit and Taproot.
- LTC: legacy, nested SegWit and native SegWit; DOGE, BCH and transparent ZEC.
- ETH/EVM Suite paths, Ledger Live and legacy paths; ETC Suite paths.
- XRP, TRX (Suite and Ledger Live), SOL (Suite, Ledger Live and root), XLM.
- Only networks configured by Suite should be consumed by the host. EVM tokens
  reuse their parent account address.
- Cardano is omitted because its extended BIP32-Ed25519 derivation needs a separate
  implementation verified against the official Ledger Cardano application.
- Requests are bounded to account indexes 0–999 and three keys per APDU. The host
  can request further batches adaptively without another network-app switch.

Public xpubs and addresses reveal financial history. The app asks for explicit
permission before any key export, stores permission only in memory, and displays
that quitting revokes access. The host must reset the session after discovery.
Do not share exported data or include it in analytics or remote logs.

## Reproducible Flex build

Run from this directory with Docker running:

```sh
docker run --rm \
  -v "$PWD:/app" \
  ghcr.io/ledgerhq/ledger-app-builder/ledger-app-dev-tools@sha256:1f93ba59ee02576f336653c712276f006d4d81f4e355b023489bb7b5bdcf390d \
  cargo ledger build flex -- --locked
```

The output files in `target/flex/release/` are:

- `accounts-discovery`: ELF, suitable for Speculos.
- `accounts-discovery.hex`: device code.
- `accounts-discovery.apdu`: installation script generated by cargo-ledger.

The pinned builder contains Flex SDK API 26 (`v26.6.5`), Rust nightly
`2025-12-05`, cargo-ledger 1.14.0, and Speculos 0.27.0. This artifact targets Flex
OS 1.6.0/1.6.1 (API 26). Match the device's OS API before installing; earlier OS
versions need a build using their matching official SDK.

Test the pure derivation policy without device syscalls:

```sh
docker run --rm \
  -v "$PWD:/app" \
  ghcr.io/ledgerhq/ledger-app-builder/ledger-app-dev-tools@sha256:1f93ba59ee02576f336653c712276f006d4d81f4e355b023489bb7b5bdcf390d \
  bash -c 'rustc --edition 2021 --test src/profiles.rs -o /tmp/profiles-test && /tmp/profiles-test'
```

## Install on your Flex

This is a development application, not a Ledger-reviewed or Ledger-signed store
application. Sideloading uses Ledger's normal secure loader and requires explicit
physical confirmation of the application identifier on the device. No seed, PIN,
attestation key or custom certificate is supplied to the host.

After building, connect and unlock the Flex by USB, return to its dashboard,
close other applications that use the device, and run on your host:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install ledgerblue==0.1.58
.venv/bin/python -m ledgerblue.runScript \
  --elfFile target/flex/release/accounts-discovery \
  --fileName target/flex/release/accounts-discovery.apdu \
  --apdu --scp
```

Verify that the device confirmation names **Accounts Discovery** and approve it
on the device. The generated installation permissions allow secp256k1 and
Ed25519 and only the fixed purpose/coin path prefixes listed in `Cargo.toml`.
The Rust builder adds `BOLOS_SETTINGS` (`0x200`) for the BLE transport. The app
exposes no setting-change command and requests no `GLOBAL_PIN`, `DERIVE_MASTER`,
or `LIBRARY` permission.
The app additionally restricts the complete derivation paths in `src/profiles.rs`.
No physical-device installation is performed by the project tests.

## Flex emulator regression tests

Start Speculos with the built ELF and the public test mnemonic below. All ports
bind only to localhost. The fixed mnemonic must never be used with real funds.

```sh
docker run --rm -d --name accounts-discovery-speculos \
  -p 127.0.0.1:5001:5000 -p 127.0.0.1:9999:9999 \
  -v "$PWD:/app:ro" \
  ghcr.io/ledgerhq/ledger-app-builder/ledger-app-dev-tools@sha256:1f93ba59ee02576f336653c712276f006d4d81f4e355b023489bb7b5bdcf390d \
  speculos --model flex --display headless --api-port 5000 --apdu-port 9999 \
  --seed "abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about" \
  /app/target/flex/release/accounts-discovery

docker exec accounts-discovery-speculos python3 /app/speculos_test.py
docker stop accounts-discovery-speculos
```

The regression script exercises real device consent controls, rejection, reset,
repeated batches, malformed and forbidden requests. It compares all 25 profiles
at account zero and eligible profiles at accounts 7/999 against independent
BIP32 and SLIP-10 derivation using the builder's host crypto libraries. The test
prints only a result and vector count; exported account data remains local.
Speculos screen events and screenshots are available at `http://localhost:5001`.
